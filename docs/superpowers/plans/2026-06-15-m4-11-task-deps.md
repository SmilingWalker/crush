## Task 5: Service -- Dependency Methods + Cycle Detection + Cascade Wake

### New file: `internal/team/dependency.go`

Contains 4 methods on `teamService`:

#### 5a. AddDependency (with cycle detection)

```go
// ErrDependencyCycle is returned when adding a dependency would create a cycle.
var ErrDependencyCycle = errors.New("dependency would create a cycle")

// ErrSelfDependency is returned when task_id == depends_on_task_id.
var ErrSelfDependency = errors.New("task cannot depend on itself")

// AddDependency creates a dependency edge taskID -> dependsOnTaskID.
// Before inserting, it runs DFS cycle detection: if dependsOnTaskID already
// transitively depends on taskID, adding this edge would create a cycle.
func (s *teamService) AddDependency(ctx context.Context, taskID, dependsOnTaskID, teamID string) error
```

**DFS cycle detection algorithm:**
```
Given proposed edge: A -> B (A depends on B)
Check: does B transitively depend on A?

Load full dependency graph for the team from DB (read tx).
Run DFS starting from B, following dependency edges:
  if we reach A, then there's already a path B ->*-> A,
  so adding A -> B creates a cycle → return ErrDependencyCycle

If DFS completes without reaching A, no cycle → insert the edge (write tx).
```

Self-dependency check: if `taskID == dependsOnTaskID`, return `ErrSelfDependency`.

#### 5b. RemoveDependency

```go
func (s *teamService) RemoveDependency(ctx context.Context, taskID, dependsOnTaskID string) error
```

Simple DELETE. Does not auto-unblock the task (caller decides if the task should now be queued).

#### 5c. OnTaskCompleted -- cascade wake

```go
// OnTaskCompleted is called when a task transitions to 'completed'.
// It walks the dependency graph: for each dependent task (task that depends
// on the completed task), checks if ALL of that dependent's dependencies are
// now completed. If so, the dependent is unblocked: status transitions from
// 'blocked' to 'queued', and if the task has an assignee, that member is
// marked as unblocked. The unblocking is recursive (DFS walk): an unblocked
// task may unblock further tasks.
// 
// Returns the set of task IDs that were unblocked (for the caller to wake
// the assigned members).
func (s *teamService) OnTaskCompleted(ctx context.Context, teamID, completedTaskID string) ([]string, error)
```

**Cascade algorithm:**
```
queue = [completedTaskID]
unblockedSet = {}

while queue is not empty:
    task = queue.pop()
    dependents = GetDependents(task)  // tasks that depend on 'task'
    for each dependent:
        deps = GetDependencies(dependent)  // what does dependent need?
        allCompleted = true
        for each dep:
            depTask = GetTask(dep.depends_on_task_id)
            if depTask.Status != TaskCompleted:
                allCompleted = false
                break
        if allCompleted:
            UpdateTask(dependent, status=TaskQueued)  // unblock
            unblockedSet.add(dependent)
            queue.push(dependent)  // cascade: this unblocked task may unblock others

return list(unblockedSet)
```

This runs in a single write tx. The recursive cascade handles chain dependencies (A blocks B, B blocks C, complete A -> unblocks B -> unblocks C).

### Update `CreateTask` method

When creating a task, if the `CreateTaskRequest` carries dependency IDs (`depends_on_task_ids`), atomically insert the dependency edges. Validation: if any dependency is already in 'completed' status, skip it (don't block on already-completed tasks).

**Update `CreateTaskRequest`:**
```go
type CreateTaskRequest struct {
    TeamID            string   `json:"team_id"`
    Title             string   `json:"title"`
    Description       string   `json:"description,omitempty"`
    CreatedByMemberID string   `json:"created_by_member_id"`
    Priority          int      `json:"priority,omitempty"`
    DependsOnTaskIDs  []string `json:"depends_on_task_ids,omitempty"` // NEW
}
```

When `DependsOnTaskIDs` is non-empty:
1. For each dependency ID, check if that task exists and is NOT completed.
2. If the dependency task is already completed, skip it (no edge inserted).
3. Check all remaining dependencies still exist.
4. Insert dependency edges.
5. If any non-completed dependency remains, set the new task's status to `blocked` (not `queued`).
6. Run cycle detection for each edge (optional but recommended -- the DFS is cheap for small graphs).

## Design Seams

1. **Migration**: goose format with `-- +goose Up/Down` + `StatementBegin/End`. File name `20260616000000_create_task_dependencies.sql`. PK is composite `(task_id, depends_on_task_id)` -- no surrogate ID column.

2. **sqlc v1.30.0 hand-authoring**: sqlc package `db` (NOT `sqlc`). Params structs follow exact naming convention `OperationNameParams`. Query functions use `q.db.QueryRowContext`/`q.db.ExecContext`/`q.db.QueryContext` internally.

3. **FK pattern**: `REFERENCES team_tasks(id) ON DELETE CASCADE` for both task_id and depends_on_task_id. `REFERENCES teams(id) ON DELETE CASCADE` for team_id. This means deleting a task cascades to delete all dependency rows where it appears as either task_id or depends_on_task_id.

4. **Cycle detection**: Runs in a read tx to load the current dependency graph, runs DFS from `dependsOnTaskID` to check if it can reach `taskID`. If DFS reaches `taskID`, the proposed edge would create a cycle. Time complexity O(V+E) where V is the number of tasks in the team's dependency graph. The DFS is bounded -- worst case visits all tasks once.

5. **Cascade wake -- single tx**: `OnTaskCompleted` runs all dependency evaluation and task unblocking in a single write tx. This is correct because the dependency graph changes are confined to the team_id scope and the Service serializes per-team writes via the DB tx.

6. **blocks/blockedBy as computed fields**: Not stored in a column, populated at read time via `GetDependencies` + `GetDependents`. The `GetTaskWithDeps` method wraps `GetTask` + dependency lookups. The existing `GetTask`/`ListTasks` methods do NOT populate blocks/blockedBy (backward compatible); callers who need deps call `GetTaskWithDeps`.

7. **No change to ClaimNextTask**: The scheduler's `ClaimNextTask` already filters `status = 'queued'` -- blocked tasks won't be claimed until they're unblocked. No changes needed to M4-03 Scheduler.

8. **CreateTask + deps**: When `CreateTaskRequest.DependsOnTaskIDs` is provided, the Service loads each dependency task in a read tx, determines if the new task should start 'queued' or 'blocked', then in a write tx: creates the task row + inserts dependency edges. Completed dependency tasks produce no edge (they don't block).
