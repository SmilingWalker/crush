# M2-04 Delegate UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render a parallel delegate group as a chat message item in crush's bubbletea TUI — a compact one-line status row (`Delegates  2 running / 1 done`) that expands to a per-child table, with running spinners, done/error/canceled status icons, and a read-only child-transcript modal opened by Enter on a completed child. This is the M2 UI surface that consumes `team.DelegateRunGroup` (M2-01, merged at agent-team tip `654cb3b6`).

**Architecture:** A new `internal/ui/chat/delegate.go` ships two UI structs (`DelegateGroupMessageItem`, `DelegateChildItem`) and a `ToolRenderer` (`DelegateGroupRenderContext`) that follow the exact patterns of `internal/ui/chat/agent.go` (`AgentToolMessageItem` embeds `*baseToolMessageItem`, custom `Animate`/`SetNestedTools`/`RenderTool`). The group item implements `chat.MessageItem`, `chat.Expandable`, `chat.Animatable`, and `chat.KeyEventHandler` (the last is how Enter-on-child signals the main model to open the modal). A new read-only `dialog.DelegateTranscript` (the child-transcript modal) implements `dialog.Dialog` and renders its body via the existing `renderPreviewBox` markdown helper. The main model wires the modal open in two small spots: a new `ActionOpenDelegateTranscript` action (mirrors `ActionSelectSession`) and a case in `Update` that calls `m.dialog.OpenDialog(dialog.NewDelegateTranscript(...))`.

The delegate runner is NOT wired into any message feed today (verified: zero references to `internal/team` anywhere in `internal/ui`). M2-04 is therefore **rendering-only**: the item types + renderer + modal + open-path are built and unit-tested in isolation, fed by directly-constructed `DelegateGroupMessageItem` values (the same way `internal/ui/model/chat_expand_test.go:30` constructs a `chat.NewAssistantMessageItem` directly). The live data path (an agent-team event → a `DelegateGroupMessageItem` injected into `Chat.SetMessages`) is explicitly out of scope and named as the follow-up; it cannot land until (a) the `Experimental.AgentTeamPreview` config flag exists and (b) a producer publishes delegate-group events. Both are pre-existing gaps M2-04 does not close.

**Tech Stack:** Go 1.26.3 (`module github.com/charmbracelet/crush`), `charm.land/bubbletea/v2` (tea.Msg/tea.Cmd), `charm.land/lipgloss/v2` (styles + `tree`), `github.com/charmbracelet/x/ansi` (Truncate/StringWidth — never byte-level ANSI), `github.com/charmbracelet/ultraviolet` (uv.Screen/uv.Rectangle for Draw). ## Design seam corrections (vs master task doc `03-m2-delegate-runner.md:433-515`)

The master task doc is the approved design intent. The following are **verified implementation deviations**, each backed by cited evidence from the codebase at agent-team tip `654cb3b6`. Every code snippet in this plan is rewritten against the real APIs.

### Seam 1: `baseToolMessageItem` is unexported — the group item is built via a render context, not a `*baseToolMessageItem` embed taken from outside the package

The master doc (`:449-454`) writes:

```go
type DelegateGroupMessageItem struct {
    *baseToolMessageItem   // <-- master doc embeds this
    Children    []*DelegateChildItem
    ...
}
```

`baseToolMessageItem` IS in `package chat` (`internal/ui/chat/tools.go:138`), so the embed is legal **from inside the package**. This is the same pattern `AgentToolMessageItem` uses (`internal/ui/chat/agent.go:29`: `*baseToolMessageItem`). **The embed is correct.** The seam is only that `baseToolMessageItem` and its constructor `newBaseToolMessageItem` (`tools.go:166`, both unexported) are only callable from within `package chat` — so the new file **must** be `internal/ui/chat/delegate.go` (package `chat`), exactly as the master doc's "涉及文件" names (`:439`). A caller outside the package cannot construct one; the plan therefore ships a `NewDelegateGroupMessageItem` constructor (exported) that internally calls `newBaseToolMessageItem`, mirroring `NewAgentToolMessageItem` (`agent.go:40`).

**Evidence:** `internal/ui/chat/agent.go:28-53` (the reference pattern), `internal/ui/chat/tools.go:137-204` (base struct + unexported constructor). Read in full during research.

### Seam 2: `agent.AgentToolResult` exists and is the right child-result type — but it must be PRODUCED from `team.DelegateResult`, not embedded

The master doc (`:456-464`) wants `DelegateChildItem.Result *agent.AgentToolResult`. **`agent.AgentToolResult` exists** (`internal/agent/agent_result.go:13-21`) with exactly the fields the UI needs: `AgentType string`, `Content string`, `TotalTokens int64`, `TotalToolUseCount int`, `TotalDurationMs int64`, `Usage agent.Usage`. This is richer than `team.DelegateResult` (which carries `Status`, a `*fantasy.AgentResult`, `Error`, `DurationMs`).

The seam: `team.DelegateResult.Result` is a `*fantasy.AgentResult` (the raw fantasy type, `internal/team/delegate_types.go:36`), NOT an `agent.AgentToolResult`. The UI must NOT depend on `fantasy` directly if it can avoid it, and it must convert a `team.DelegateResult` into the UI-facing `DelegateChildItem`. **Decision:** ship a converter `NewDelegateChildItem(res team.DelegateResult) DelegateChildItem` in `delegate.go` that maps:

- `AgentType` ← `res.Result.Response.Content...` is wrong (the UI should not parse fantasy). Instead `AgentType` is taken from the **task** (`team.DelegateTask.AgentID`), which the group already holds (`DelegateRunGroup.Tasks[i].AgentID`). The converter therefore takes the task too: `NewDelegateChildItem(task team.DelegateTask, res team.DelegateResult)`.
- `Status` ← a derived UI status string (`"running"|"done"|"error"|"canceled"`) from `res.Status` (a `agent.TurnStatus`): `""`→`"running"`, `agent.TurnCompleted`→`"done"`, `agent.TurnFailed`→`"error"`, `agent.TurnCanceled`→`"canceled"`.
- `Result` ← `agent.AgentToolResult` built from `res.Result` (a `*fantasy.AgentResult`) via a small local projection (copying `buildAgentToolResult`'s shape for the fields the UI reads: `Content`, `TotalTokens`, `TotalToolUseCount`, `TotalDurationMs`). Because `buildAgentToolResult` is unexported in `package agent`, the plan re-derives these fields from `res.Result` directly (the fantasy `AgentResult` exposes `Response.Content.Text()`, `TotalUsage.InputTokens`, `TotalUsage.OutputTokens`, and `Steps` for tool-count — all public). To keep M2-04 lean, `TotalToolUseCount` is read off `res.Result` via the same loop `agent_result.go:58-` uses (count `ToolCallContent` across steps); if the field proves awkward it defaults to 0 (the count is display-only).
- `ChildSessionID` ← `res.ChildSessionID`.
- `DurationMs` ← `res.DurationMs` (fall back to `res.Result`-derived if zero — but `res.DurationMs` is always set by the runner, `delegate_runner.go:152`, so use it directly).
- `ActivityDesc` ← for `running` children, a static `"working…"`; for terminal children, the first line of `Result.Content` truncated. This is the line the master doc's `RenderDelegateExpanded` (`:486`) prints in the last column.
- `ToolUseCount` ← `Result.TotalToolUseCount`.

A nil `res.Result` (failed/canceled before any fantasy result) produces a zero-valued `agent.AgentToolResult` with `Content` = `res.Error` (so the child line shows the failure reason). This keeps the UI usable on the failure paths M2-01's tests exercise (`TestDelegateRunner_PanicRecovery`).

**Evidence:** `internal/agent/agent_result.go:9-54` (`AgentToolResult` + `buildAgentToolResult`), `internal/team/delegate_types.go:33-40` (`DelegateResult.Result *fantasy.AgentResult`), `internal/team/delegate_runner.go:143-160` (Result/DurationMs/ChildSessionID populated).

### Seam 3: `Experimental.AgentTeamPreview` / `Experimental.AgentTeam` DO NOT EXIST — the flag-off gate (#5) is a package-local switch defaulting OFF

This is the single biggest correction. The master doc acceptance #5 (`:513`) says "flag off 时不渲染 delegate UI", and the team-lead's seam brief points at `Experimental.AgentTeamPreview`/`AgentTeam` in `internal/config`. **Research result: neither the field nor any `Experimental` config section exists.** Evidence:

- `grep -n "AgentTeamPreview|AgentTeam|Experimental" internal/config/` → **no matches** in the entire `internal/config` package.
- `internal/config/config.go:272-295` (the `Options` struct, read in full) has no `Experimental` field. The closest flags are `Debug`, `DisableAutoSummarize`, etc. — nothing gating agent-team mode.
- The flag is only a **proposal**: `docs/agent-team-mode/12-open-architecture-issues.md:147` (Decision dated 2026-06-02): "在 `internal/config.Options` 新增 `Experimental *ExperimentalOptions`，字段为 `AgentTeamPreview` 和 `AgentTeam`，默认 nil/false." It was never implemented. (`docs/agent-team-mode/00-technical-design.md:141` repeats the proposal.)

**Decision for M2-04:** Do NOT add the config flag — that is a config-layer task with its own migration/jsonschema/`load_test.go` surface, and `12-open-architecture-issues.md:151` lists `internal/config` as an impacted module for a separate decision. Instead, M2-04 ships a **package-local gate function** in `delegate.go`:

```go
// delegateUIEnabled gates whether the delegate group item renders. Until the
// Experimental.AgentTeamPreview config flag lands (open architecture issue #8,
// docs/agent-team-mode/12-open-architecture-issues.md:147), the gate is a
// package-level switch so the renderer is inert by default and acceptance #5
// ("flag off → no delegate UI") is testable in isolation. When the flag ships,
// swap this single read for `cfg.Experimental.AgentTeamPreview` (a one-line
// change; the rest of the renderer is flag-agnostic).
var delegateUIEnabled atomic.Bool // default false
```

The renderer's `RenderTool` returns the **empty string** when `!delegateUIEnabled.Load()` (so the item contributes no lines), and `NewDelegateGroupMessageItem` is still callable for tests (the tests set the switch true). Acceptance #5 is then a unit test: construct a group item, assert `Render(width)` is `""` while the switch is off, flip the switch, assert it renders. This mirrors how feature flags are often pre-wired behind a switch before the config plumbing lands, keeps M2-04 self-contained, and documents the exact one-line follow-up for the config task.

**This keeps M2-04 strictly additive to `internal/ui`** (no `internal/config` edit), matching the team-lead's "不碰 internal/config" implicit scope (the brief only asks to *verify* the flag, not add it).

### Seam 4: The child-transcript modal is a `dialog.Dialog`, opened via a new action — NOT via `KeyEventHandler` returning a dialog directly

The master doc acceptance #4 (`:512`) says: "选中已完成 child → Enter → 打开 child transcript modal（只读，Esc 关闭）". The crush dialog system (`internal/ui/dialog/dialog.go:32-42`) requires a modal to implement `Dialog` (`ID()`, `HandleMsg(msg) Action`, `Draw(scr, area) *tea.Cursor`), and modals are opened by the **main `UI` model** via `m.dialog.OpenDialog(d)` (`internal/ui/model/ui.go:742`, used at `:3422`/`:3448`/`:3465`/`:3477`/etc.). Sub-components do not open dialogs themselves (the AGENTS.md "Centralized Message Handling" rule, `internal/ui/AGENTS.md:56-77`).

So the signal flow for Enter-on-child is:

1. The delegate group item implements `chat.KeyEventHandler.HandleKeyEvent(key) (bool, tea.Cmd)` (`internal/ui/chat/messages.go:46-49`). `Chat.HandleKeyMsg` (`internal/ui/model/chat.go:618-625`) dispatches the keypress to the **selected** item's `HandleKeyEvent` when the list is focused.
2. On `Enter`, `HandleKeyEvent` returns a `tea.Cmd` that emits a new `OpenDelegateTranscriptMsg{GroupID, ChildIndex}` (a plain `tea.Msg`), so the main model's `Update` switch can react. Returning a `tea.Cmd` (not a `dialog.Dialog`) is the only way a list item can talk to the main model — the item has no handle to `m.dialog`.
3. The main model's `Update` has a new `case OpenDelegateTranscriptMsg:` that builds a `dialog.NewDelegateTranscript(com, groupID, child)` and calls `m.dialog.OpenDialog(...)`. The child's content (`agent.AgentToolResult.Content`) is captured at open time.

The modal itself (`dialog.DelegateTranscript`):
- `ID()` returns `"delegate-transcript"` (new const `DelegateTranscriptID`).
- `HandleMsg` returns `ActionClose{}` on Esc (reusing `dialog.CloseKey`, `dialog.go:24-27`, the same key reasoning.go uses at `reasoning.go:116`). No selection, no input — it is read-only.
- `Draw` builds a centered view via `NewRenderContext` (`dialog/common.go:98`) with `Title = "Delegate Transcript"` and a body rendered by the existing `renderPreviewBox` (`dialog/preview_box.go:25`, the markdown left-border helper already used by the questions dialog, `questions.go:520`). Width capped like `reasoning.go:167` (`min(maxWidth, area.Dx())`).

This mirrors `dialog.Reasoning` (`reasoning.go:1-319`, read in full) as the structural template, minus the filterable list (a transcript is a single markdown blob, not a selectable list). The transcript body content comes from `child.Result.Content` (markdown text the delegate produced).

**Why a NEW `OpenDelegateTranscriptMsg` instead of reusing `ActionOpenDialog{DialogID}`:** `ActionOpenDialog{DialogID}` (`dialog/actions.go:28-31`) is a `dialog.Action` returned from `Dialog.HandleMsg`, but the Enter keypress originates in a **list item**, not a dialog. List items communicate via `tea.Cmd` → `tea.Msg` → the main `Update` switch, not via `dialog.Action`. The new msg type is the correct Elm-architecture hop. (If the team-lead prefers, the msg can instead be an `ActionOpenDelegateTranscript{GroupID, ChildIndex}` added to `dialog/actions.go` and routed through the existing `dialog.Update` path — but that path only fires when a dialog is already front-most (`dialog.go:131-143`), which is not the case when the user is in the chat list. The plain `tea.Msg` is correct.)

**Evidence:** `internal/ui/dialog/dialog.go:32-48` (Dialog iface), `:24-27` (CloseKey), `internal/ui/dialog/reasoning.go:112-200` (reference modal), `internal/ui/dialog/common.go:61-160` (RenderContext), `internal/ui/dialog/preview_box.go:25` (renderPreviewBox), `internal/ui/chat/messages.go:46-49` (KeyEventHandler), `internal/ui/model/chat.go:618-625` (HandleKeyMsg dispatch), `internal/ui/model/ui.go:742` (OpenDialog), `:3357-3391` (openDialog switch).

### Seam 5: The group item is a list item, not a tree of list items — child rows render inline (like `AgentToolMessageItem`'s nested tools)

The master doc (`:449-505`) models the group as a `DelegateGroupMessageItem` with `Children []*DelegateChildItem`. In crush's list model, **only the group is a list item**; the children render as inline lines inside the group's `Render` output (exactly how `AgentToolMessageItem` embeds `nestedTools` and renders them as `tree.Root(header).Child(...)` lines, `agent.go:166-171`). The list's `idInxMap` (`internal/ui/model/chat.go:240-246`) only maps the **parent** ID; children are not independently selectable list entries.

**Implication for Enter-on-child:** because children are not list items, the group's `HandleKeyEvent` must track its own "selected child" cursor (an index into `Children`) and respond to Up/Down/Enter itself. This is a small amount of state on the group item (`selectedChild int`), bumped into the parent's `Versioned` on change so the list re-renders. The Up/Down cursor is only active when the group is focused **and** expanded; otherwise Up/Down passes through to the list (chat navigation). `HandleKeyEvent` returns `(true, cmd)` when it consumes the key (cursor move or Enter) and `(false, nil)` when it does not (so `Chat.HandleKeyMsg` falls back to default nav).

The master doc's two render functions (`RenderDelegateCompact`, `RenderDelegateExpanded`, `:466-494`) become the two branches of a single `RenderTool` on `DelegateGroupRenderContext`: compact = one status line; expanded = status line + per-child rows (status icon + agent type + tool-count + duration + activity). The expanded rows also underline/arrow the `selectedChild` (focused row) so the user sees which child Enter will target. The `statusIcon` helper (`:496-504`) is kept verbatim but uses `styles.TodoCompletedIcon` (`"✓"`, `styles.go:40`) for done to match the existing todo icon vocabulary rather than introducing a fresh glyph set.

**Evidence:** `internal/ui/chat/agent.go:166-171` (inline nested-tool rendering pattern), `internal/ui/chat/agent.go:104-119` (SetNestedTools always bumps), `internal/ui/chat/messages.go:46-49` (KeyEventHandler), `internal/ui/styles/styles.go:40-42` (icon constants).

```go
// DelegateGroupMessageItem renders a parallel delegate group (a
// team.DelegateRunGroup) as a single chat list item. It follows the
// AgentToolMessageItem pattern (internal/ui/chat/agent.go:28): it embeds
// *baseToolMessageItem for caching/versioning/animation, holds its child rows
// inline (children are NOT list items — they render as lines inside Render,
// like agent.go's nested tools), and implements Expandable + KeyEventHandler
// for the compact/expanded toggle and the Enter-opens-modal interaction.
type DelegateGroupMessageItem struct {
	*baseToolMessageItem

	groupID       string
	children      []DelegateChildItem
	selectedChild int // cursor into children; only meaningful when Expanded
}

var (
	_ ToolMessageItem  = (*DelegateGroupMessageItem)(nil)
	_ Expandable       = (*DelegateGroupMessageItem)(nil)
	_ Animatable       = (*DelegateGroupMessageItem)(nil)
	_ KeyEventHandler  = (*DelegateGroupMessageItem)(nil)

// NewDelegateGroupMessageItem creates the group item. toolCall.ID is the list
// item's ID (the same ID the message-extraction path would assign); groupID is
// the team.DelegateRunGroup.ID, carried so OpenDelegateTranscriptMsg can name
// the group.
func NewDelegateGroupMessageItem(
	sty *styles.Styles,
	groupID string,
	toolCall message.ToolCall,
	result *message.ToolResult,
	canceled bool,
) *DelegateGroupMessageItem {
	d := &DelegateGroupMessageItem{groupID: groupID}
	d.baseToolMessageItem = newBaseToolMessageItem(sty, toolCall, result, &DelegateGroupRenderContext{group: d}, canceled)
	// Keep the parent spinning while any child is still running.
	d.spinningFunc = func(state SpinningState) bool {
		for _, c := range d.children {
			if c.Status == "running" {
				return true
			}
		}
		return false
	}
	return d
}

// SetChildren replaces the child rows. Always bumps (mirrors
// AgentToolMessageItem.SetNestedTools at agent.go:104): the live update path
// mutates children in place then calls SetChildren with the same slice, so
// pointer-equality dedupe would skip a needed re-render.
func (d *DelegateGroupMessageItem) SetChildren(children []DelegateChildItem) {
	if d.selectedChild >= len(children) {
		d.selectedChild = max(0, len(children)-1)
	}
	d.children = children
	d.clearCache()
	d.Bump()
}

// ToggleExpanded implements Expandable. Mirrors baseToolMessageItem's existing
// expand contract: returns whether the item is now expanded.
func (d *DelegateGroupMessageItem) ToggleExpanded() bool {
	d.expandedContent = !d.expandedContent
	d.clearCache()
	d.Bump()
	return d.expandedContent
}

// Animate forwards spinner ticks to the parent anim (mirrors
// baseToolMessageItem.Animate at tools.go:307, with the ID gate) so running
// children show a live spinner. Bumps the version so the list cache re-renders
// the new frame.
func (d *DelegateGroupMessageItem) Animate(msg anim.StepMsg) tea.Cmd {
	if msg.ID != d.toolCall.ID {
		return nil
	}
	if !d.isSpinning() {
		return nil
	}
	d.Bump()
	return d.anim.Animate(msg)
}

// HandleKeyEvent implements KeyEventHandler. When the group is expanded and
// focused it owns Up/Down (move the child cursor) and Enter (open the selected
// child's transcript if that child is terminal). Returns (true, nil/ cmd) when
// the key is consumed so Chat.HandleKeyMsg does not fall through to default
// navigation; (false, nil) otherwise.
func (d *DelegateGroupMessageItem) HandleKeyEvent(key tea.KeyMsg) (bool, tea.Cmd) {
	if !d.expandedContent || len(d.children) == 0 {
		return false, nil
	}
	switch key.String() {
	case "up", "k":
		if d.selectedChild > 0 {
			d.selectedChild--
			d.clearCache()
			d.Bump()
		}
		return true, nil
	case "down", "j":
		if d.selectedChild < len(d.children)-1 {
			d.selectedChild++
			d.clearCache()
			d.Bump()
		}
		return true, nil
	case "enter":
		if d.selectedChild < 0 || d.selectedChild >= len(d.children) {
			return true, nil
		}
		c := d.children[d.selectedChild]
		if c.Status == "running" {
			// Consumed (no fallthrough) but no modal — the transcript only
			// exists for completed children.
			return true, nil
		}
		return true, func() tea.Msg {
			return OpenDelegateTranscriptMsg{GroupID: d.groupID, ChildIndex: d.selectedChild}
		}
	}
	return false, nil
}

// DelegateGroupRenderContext is the ToolRenderer for the delegate group.
type DelegateGroupRenderContext struct {
	group *DelegateGroupMessageItem
}

// RenderTool implements ToolRenderer. When the flag gate is off it returns ""
// (acceptance #5). Otherwise compact = a single status line; expanded = the
// status line plus a per-child row.
func (r *DelegateGroupRenderContext) RenderTool(sty *styles.Styles, width int, opts *ToolRenderOpts) string {
	if !delegateUIEnabled.Load() {
		return ""
	}
	cappedWidth := cappedMessageWidth(width)
	running, done, failed := 0, 0, 0
	for _, c := range r.group.children {
		switch c.Status {
		case "running":
			running++
		case "done":
			done++
		default: // error | canceled
			failed++
		}
	}

	// Compact status line: "Delegates  N running / M done" (+ "/ K failed" if any).
	statusParts := []string{fmt.Sprintf("%d running", running), fmt.Sprintf("%d done", done)}
	if failed > 0 {
		statusParts = append(statusParts, fmt.Sprintf("%d failed", failed))
	}
	statusLine := "Delegates  " + strings.Join(statusParts, " / ")
	header := toolHeader(sty, opts.Status, "Delegates", cappedWidth, opts.Compact, statusLine)
	if opts.Compact || !r.group.expandedContent {
		// Show the spinner when any child is running (matches agent.go:178).
		if !opts.HasResult() && running > 0 {
			return lipgloss.JoinVertical(lipgloss.Left, header, "", opts.Anim.Render())
		}
		return header
	}

	// Expanded: one row per child.
	var rows []string
	for i, c := range r.group.children {
		dur := ""
		if c.DurationMs > 0 {
			dur = formatDurationMs(c.DurationMs)
		}
		tools := ""
		if c.ToolUseCount > 0 {
			tools = fmt.Sprintf("%d tools", c.ToolUseCount)
		}
		row := fmt.Sprintf("%s %-14s %-9s %6s %7s  %s",
			statusIcon(c.Status), c.AgentType, c.Status, tools, dur, c.ActivityDesc)
		if i == r.group.selectedChild {
			row = sty.Tool.AgentPrompt.Render(row) // highlight the focused row
		}
		rows = append(rows, row)
	}
	body := strings.Join(rows, "\n")
	if !opts.HasResult() && running > 0 {
		body = lipgloss.JoinVertical(lipgloss.Left, body, "", opts.Anim.Render())
	}
	return joinToolParts(header, sty.Tool.Body.Render(body))
}

// formatDurationMs renders a millisecond duration compactly (e.g. "1.2s",
// "340ms"). Kept minimal — display only.
func formatDurationMs(ms int64) string {
	if ms < 1000 {
		return fmt.Sprintf("%dms", ms)
	}
	return fmt.Sprintf("%.1fs", float64(ms)/1000)
}
```

```go
package dialog

import (
	tea "charm.land/bubbletea/v2"
	"github.com/charmbracelet/crush/internal/ui/common"
	"github.com/charmbracelet/crush/internal/ui/styles"
	uv "github.com/charmbracelet/ultraviolet"
)

const (
	// DelegateTranscriptID is the dialog ID for the read-only child-transcript
	// modal opened from a DelegateGroupMessageItem.
	DelegateTranscriptID              = "delegate-transcript"
	delegateTranscriptMaxWidth        = 90
	delegateTranscriptMaxHeight       = 24
	delegateTranscriptPreviewMaxLines = 18
)

// DelegateTranscript is a read-only modal showing one delegate child's result
// content (the markdown the delegate returned). Opened by Enter on a completed
// child in a DelegateGroupMessageItem; closed by Esc. Mirrors dialog.Reasoning
// structurally but drops the selectable list (a transcript is a single markdown
// blob rendered via renderPreviewBox).
type DelegateTranscript struct {
	com        *common.Common
	groupID    string
	agentType  string
	content    string // markdown text (agent.AgentToolResult.Content)
}

var _ Dialog = (*DelegateTranscript)(nil)

// NewDelegateTranscript builds the modal. agentType is shown in the title
// (e.g. "Delegate Transcript · explore"); content is the markdown body.
func NewDelegateTranscript(com *common.Common, groupID, agentType, content string) *DelegateTranscript {
	return &DelegateTranscript{
		com:       com,
		groupID:   groupID,
		agentType: agentType,
		content:   content,
	}
}

// ID implements Dialog.
func (d *DelegateTranscript) ID() string { return DelegateTranscriptID }

// HandleMsg implements Dialog. Esc closes; everything else is a no-op (the
// modal is read-only — no selection, no input).
func (d *DelegateTranscript) HandleMsg(msg tea.Msg) Action {
	k, ok := msg.(tea.KeyMsg)
	if !ok {
		return nil
	}
	if k.Type == tea.KeyEsc {
		return ActionClose{}
	}
	return nil
}

// render builds the modal's view string (the same split reasoning.go uses:
// Draw delegates here, and tests assert on the string directly).
func (d *DelegateTranscript) render(width int) string {
	t := d.com.Styles
	w := max(0, min(delegateTranscriptMaxWidth, width))
	innerWidth := w - t.Dialog.View.GetHorizontalFrameSize()

	rc := NewRenderContext(t, w)
	if d.agentType != "" {
		rc.Title = "Delegate Transcript · " + d.agentType
	} else {
		rc.Title = "Delegate Transcript"
	}

	body := renderPreviewBox(previewBoxConfig{
		content:  d.content,
		width:    innerWidth,
		maxLines: delegateTranscriptPreviewMaxLines,
		styles:   t,
	})
	rc.AddPart(body)

	return rc.Render()
}

// Draw implements Dialog. Centers the rendered view (no cursor — read-only).
func (d *DelegateTranscript) Draw(scr uv.Screen, area uv.Rectangle) *tea.Cursor {
	width := area.Dx()
	view := d.render(width)
	DrawCenter(scr, area, view)
	return nil
}
```
