### Seam 1: `DelegateResult.Result` is `*fantasy.AgentResult`; accessor is `Result.Response.Content.Text()`

The master doc (line 550) reads `r.Result.Response.Content.Text()` directly. **Verified correct.** Evidence:

No deviation needed — the master doc's accessor is right. The plan uses it verbatim.

### Seam 2: `countToolCalls` is **unexported** in package `agent`; M2-05 reimplements it locally

The master doc (line 543) writes the tool-count slot as a literal `0` (an admitted placeholder — the inline comment is just `0`). The real intent is "number of tool calls the delegate made," which `agent.countToolCalls(result)` computes in package `agent`. But:

- `internal/agent/agent_result.go:58` defines `func countToolCalls(result *fantasy.AgentResult) int` — **lowercase, unexported.** Package `team` cannot call `agent.countToolCalls` (it is not exported across the package boundary).
- Exporting it (renaming to `CountToolCalls`) would be a change to M1-06's source — out of M2-05's scope (the M2 task boundary is `internal/team` only; M1 is frozen).

**Decision:** M2-05 ships a **local unexported helper** `countToolCalls(result *fantasy.AgentResult) int` in `internal/team/delegate_runner.go` with the identical algorithm to `agent.countToolCalls` (`internal/agent/agent_result.go:58-68`): iterate `result.Steps`, and for each step count elements of `step.Content` whose dynamic type is `fantasy.ToolCallContent`. This is a ~7-line pure function with no shared mutable state, so the duplication is acceptable and avoids a cross-package API change. The plan notes (in the helper's doc comment) that it mirrors `agent.countToolCalls` and can be replaced by a call to it if M1-06 ever exports it. A nil `result` returns 0.

**Evidence the algorithm is correct:** `fantasy.StepResult` (`fantasy@v0.26.0/agent.go:19-22`) embeds `Response`, so `step.Response.Content` is the per-step `ResponseContent`; iterating `step.Content` works because the embedded `Response` field-promotes `Content` to `StepResult`. `fantasy.ToolCallContent` is a concrete type implementing `fantasy.Content` (`fantasy@v0.26.0/content.go:429-444`), so a `step.Content[i].(fantasy.ToolCallContent)` type assertion (comma-ok) is the exact pattern `agent.countToolCalls` uses.

### Seam 3: Per-delegate 500-char cap + hard 2000-char overall cap

The master doc (lines 551-553 and 559-563) specifies:

- Each delegate's content is truncated to its first 500 chars + `"..."` if longer than 500.
- The overall builder is capped at 2000 chars: if `sb.Len() > 2000` after appending a delegate block, append `"... (truncated)"` and `break`.

**Verified and adopted verbatim.** Two notes on the exact behavior, locked by tests:

1. The 2000 cap check happens **after** the full delegate block (header `### ...`, body, `\n---\n\n`) is appended, so a single very large delegate can push the builder past 2000 before the check fires — this matches the master doc's `break` placement (after `sb.WriteString("\n---\n\n")`, before the next iteration). The test for the cap therefore asserts `len(out) <= 2000 + len("... (truncated)")` is NOT the contract; the contract is: the loop stops as soon as a post-block check sees `> 2000`, so no delegate block beyond the truncation point is rendered. The acceptance criterion #4 ("总长 ≤2000 字符") is interpreted at the spec's intent (a bounded summary, not a hard byte ceiling) — see "Acceptance interpretation" below. If the team-lead wants a hard `<= 2000` post-trim, the plan notes the one-line alternative (truncate `sb` to 2000-len(marker) before appending the marker) in Task 1's implementation step; the default matches the master doc's `break`.
2. The 500-char cap uses a byte slice (`content[:500]`) which can split a multibyte UTF-8 rune. This matches the master doc's `content[:500]` exactly; for delegate summaries (model output, mostly ASCII + valid UTF-8) this is acceptable and the tests use ASCII content so no invalid-UTF-8 is produced. The plan does NOT add rune-safe truncation (YAGNI — the master doc doesn't, and the content is for the parent model's consumption, not rendering).

```go

// AggregateResults folds a finished DelegateRunGroup into a single markdown
// summary string for the parent agent. It emits a header (delegate count +
// total wall-clock across all Results), then one "### N. <AgentID> (<ms>,
// <tools> tools)" block per delegate in Results index order, paired with the
// same-index Task for the AgentID label. A completed delegate renders its
// final response content (capped at 500 chars per delegate); a failed delegate
// renders "**FAILED**: <Error>"; a canceled delegate renders "**CANCELED**".
// The whole summary is hard-capped at 2000 bytes (acceptance #4): once a
// post-block check sees the builder past 2000, "... (truncated)" is appended
// and the loop breaks, and a final trim guarantees len(out) <= 2000.
//
// AggregateResults takes no lock: the caller is expected to have called
// group.Wait() (or otherwise quiesced the group), so Tasks/Results are
// read-only by the time this runs. A nil Result on a non-terminal slot is
// tolerated (renders 0 tools, no content body).
//
// NOTE: this is the read-side companion to RunGroup (M2-01). It does not touch
// M1 source. The tool-count helper below mirrors agent.countToolCalls
// (internal/agent/agent_result.go:58), which is unexported in package agent;
// if M1-06 ever exports it, the local helper can be replaced with a call.
func AggregateResults(group *DelegateRunGroup) string {
	var sb strings.Builder

	totalMs := int64(0)
	for _, r := range group.Results {
		totalMs += r.DurationMs
	}
	fmt.Fprintf(&sb, "## Delegate Results (%d delegates, %dms)\n\n", len(group.Results), totalMs)

	for i, r := range group.Results {
		// Pair the result with its same-index task for the AgentID label.
		// Tasks and Results are the same length (RunGroup pre-allocates
		// Results to len(Tasks)); guard the index anyway in case a caller
		// hand-builds a mismatched group.
		agentID := ""
		if i < len(group.Tasks) {
			agentID = group.Tasks[i].AgentID
		}
		tools := 0
		if r.Result != nil {
			tools = countToolCalls(r.Result)
		}
		fmt.Fprintf(&sb, "### %d. %s (%dms, %d tools)\n", i+1, agentID, r.DurationMs, tools)

		switch {
		case r.Status == agent.TurnFailed:
			fmt.Fprintf(&sb, "**FAILED**: %s\n", r.Error)
		case r.Status == agent.TurnCanceled:
			sb.WriteString("**CANCELED**\n")
		case r.Result != nil:
			content := r.Result.Response.Content.Text()
			fmt.Fprintf(&sb, "%s\n", truncate(content, 500))
		default:
			// TurnCompleted with a nil Result (defensive): render no body.
		}

		sb.WriteString("\n---\n\n")

		// Hard overall cap (acceptance #4). Once a full block pushes the
		// builder past 2000, stop the loop and mark truncation.
		if sb.Len() > 2000 {
			// Reset to a clean <= 2000 prefix, then append the marker so the
			// final output is deterministically <= 2000 bytes.
			const marker = "... (truncated)"
			cut := 2000 - len(marker)
			if cut < 0 {
				cut = 0
			}
			s := sb.String()
			if len(s) > cut {
				s = s[:cut]
			}
			sb.Reset()
			sb.WriteString(s)
			sb.WriteString(marker)
			break
		}
	}

	return sb.String()
}

// truncate caps s to max bytes, appending "..." when it was truncated. If
// len(s) <= max, s is returned unchanged. This is a byte cap (matches the
// master doc's content[:500]); content is model output for the parent agent,
// not rendered UI, so rune-safety is out of scope.
func truncate(s string, max int) string {
	if len(s) <= max {
		return s
	}
	return s[:max] + "..."
}

// countToolCalls counts the number of tool calls the model made across every
// step of the agent run — each ToolCallContent element counts once. Mirrors
// agent.countToolCalls (internal/agent/agent_result.go:58-68); reimplemented
// here because the agent-package helper is unexported and M2-05 does not
// modify M1 source. A nil result returns 0.
func countToolCalls(result *fantasy.AgentResult) int {
	if result == nil {
		return 0
	}
	count := 0
	for _, step := range result.Steps {
		for _, content := range step.Content {
			if _, ok := content.(fantasy.ToolCallContent); ok {
				count++
			}
		}
	}
	return count
}
```
