## Design seam corrections (vs master task doc `05-m4-long-lived-teammate.md:257-379`)

### Seam 1: File name `team_runner.go` (NOT `runner.go`)

The master doc says `internal/team/runner.go` (:263). **Decision:** use `internal/team/team_runner.go` for consistency with the existing `member_runner.go` naming convention in the same package. This avoids ambiguity (what is `runner.go` — TurnRunner? DelegateRunner? MemberRunner?).

### Seam 2: `Service` interface (NOT `TeamService`)

The master doc uses `TeamService` (:311). The actual interface in M3-05 `service.go:124` is named `Service`. The `teamRunner` struct field will be `svc Service` to match the existing codebase.

### Seam 3: `SpawnMember` signature — member created in DB first, then MemberRunner

The master doc (:336-347) shows `SpawnMember` creating the member in DB as step 2. **Decision:** `SpawnMember` first calls `svc.SpawnMember(ctx, SpawnMemberRequest{...})` to persist the member, then creates a `MemberRunner` from the returned `TeamMember`, starts it, and registers it. The memberID parameter is the ID returned by the DB insert, not caller-provided (unlike the master doc which shows memberID as a parameter). Actually — re-reading the master doc signature `SpawnMember(ctx, teamID, memberID, spec)` has memberID as input. **Clarification:** the caller passes memberID and the name/role come from the spec. But the M3-05 `SpawnMemberRequest` generates the ID server-side. **Decision:** we diverge from the master doc signature — `SpawnMember` takes `ctx, teamID, name, role, agentProfile string, spec AgentSpec` and calls the service's `SpawnMember` which returns the generated ID. The TeamRunner interface method becomes `SpawnMember(ctx context.Context, teamID, name, role, agentProfile string, spec AgentSpec) (TeamMember, error)` — returning the created member.

### Seam 4: `StopMode` granularity vs MemberRunner.Stop()

The master doc defines `StopGraceful`/`StopCancel`/`StopForce` (:268-272). But M4-01's `MemberRunner.Stop()` (:148-158) only has a single `Stop()` method (no mode parameter) — it cancels the context and transitions to stopped. **Decision:** `StopMode` is respected at the TeamRunner level:
- `StopGraceful`: wait for current turn to complete (monitor member State → idle), then call `mr.Stop()`
- `StopCancel`: call `mr.Stop()` immediately (cancels context, aborts current turn)
- `StopForce`: call `mr.Stop()` immediately (same as StopCancel for M4-02; M4-07 may add force-kill)

For M4-02, `StopGraceful` polls member state with a timeout; `StopCancel`/`StopForce` just call `Stop()`.

### Seam 5: `CancelMemberTurn` delegates to MemberRunner internals

The master doc (:349-365) shows CancelMemberTurn doing CAS → cancel → wait → flush → terminal. But `MemberRunner` owns its own state machine and `handleWake` is unexported. **Decision:** `CancelMemberTurn` does a CAS check on the member state via RLock, then calls `mr.Stop()` (which cancels the loop context). The member's `handleWake` detects `ctx.Done()` and transitions to idle (M4-01 :271-274). The terminal state write is handled by MemberRunner internally. For M4-02, `CancelMemberTurn` is effectively `StopMember` with audit logging — full cancel-semantics (CAS canceling_turn → cancel → wait) land in M4-07 when shutdown ownership is finalized.

### Seam 6: `MemberRuntimeState` fields — what we can observe today

The master doc defines `MemberRuntimeState` (:298-304) with `CurrentTask`/`CurrentTool`/`ActivityDesc`/`CostMicros`. M4-01 `MemberRunner` exposes `ID`, `TeamID`, `Spec`, `State` (exported fields). It does NOT expose current task/tool/activity/cost yet — those are M4-05 (PromptEnvelope) and M4-12 (Cost Accounting) territory. **Decision:** `MemberRuntimeState` for M4-02 carries `State`, `Role` (from DB), `CurrentRunID`. `CurrentTask`/`CurrentTool`/`ActivityDesc`/`CostMicros` are zero-value placeholders until their owning milestones land.

  func (t *teamRunner) SpawnMember(ctx context.Context, teamID, name, role, agentProfile string, spec AgentSpec) (TeamMember, error) {
      // 1. Persist member via service.
      dbMember, err := t.svc.SpawnMember(ctx, SpawnMemberRequest{
          TeamID:       teamID,
          Name:         name,
          Role:         role,
          AgentProfile: agentProfile,
      })
      if err != nil {
          return TeamMember{}, fmt.Errorf("spawn member in db: %w", err)
      }

      // 2. Create MemberRunner.
      mr := NewMemberRunner(dbMember.ID, teamID, spec, t.factory, t.svc)

      // 3. Start the runner (launches loop goroutine).
      if err := mr.Start(ctx); err != nil {
          return TeamMember{}, fmt.Errorf("start member runner: %w", err)
      }

      // 4. Register in member map.
      t.mu.Lock()
      t.members[dbMember.ID] = mr
      t.mu.Unlock()

      return dbMember, nil
  }
  ```

  func (t *teamRunner) StopMember(ctx context.Context, teamID, memberID string, mode StopMode) error {
      t.mu.RLock()
      mr, ok := t.members[memberID]
      t.mu.RUnlock()
      if !ok {
          return fmt.Errorf("member %s not found in team %s", memberID, teamID)
      }

      switch mode {
      case StopGraceful:
          // Poll for idle state with timeout, then stop.
          deadline := time.Now().Add(30 * time.Second)
          for time.Now().Before(deadline) {
              mr.mu.Lock()
              state := mr.State
              mr.mu.Unlock()
              if state == MemberIdle || state == MemberStopped || state == MemberFailed {
                  break
              }
              select {
              case <-ctx.Done():
                  return ctx.Err()
              case <-time.After(100 * time.Millisecond):
              }
          }
          mr.Stop()
      case StopCancel, StopForce:
          mr.Stop()
      }
      return nil
  }
  ```

  Note: `mr.mu` is an exported field `mu sync.Mutex` on `MemberRunner` (:70) — we access it directly since we're in the same package (`package team`). This is package-internal coupling, consistent with the existing test code that accesses `mr.mu` directly (e.g., member_runner_test.go:220-222).

  func (t *teamRunner) CancelMemberTurn(ctx context.Context, req CancelMemberTurnRequest) error {
      t.mu.RLock()
      mr, ok := t.members[req.MemberID]
      t.mu.RUnlock()
      if !ok {
          return fmt.Errorf("member %s not found in team %s", req.MemberID, req.TeamID)

      if mr.State == MemberStopped || mr.State == MemberFailed {
          mr.mu.Unlock()
          return nil
      }
      mr.mu.Unlock()

      // Call Stop which cancels context and transitions to Stopped.
      mr.Stop()
      return nil
  }

      t.mu.RLock()
      defer t.mu.RUnlock()

      status := TeamRuntimeStatus{
          TeamID:  teamID,
          Members: make(map[string]MemberRuntimeState, len(t.members)),

      for id, mr := range t.members {
          if mr.TeamID != teamID {

## Task 5: Goroutine leak test + full acceptance suite

- [ ] **Step 1: Write goroutine leak test for SpawnMember**

  ```go
  func TestTeamRunner_SpawnMember_NoGoroutineLeak(t *testing.T) {
      svc, _ := newServiceFixture(t)
      snap, err := svc.CreateTeam(context.Background(), CreateTeamRequest{
          WorkspaceID: "ws-leak", LeaderSessionID: "lead-leak", Name: "leak-test",
      })
      require.NoError(t, err)

      mockRunner := &recordingTurnRunner{
          runResult: agent.TurnRunResult{Status: agent.TurnCompleted},
      }
      factory := &stubAgentFactory{runner: mockRunner}
      tr := NewTeamRunner(svc, factory)

      before := runtime.NumGoroutine()

      member, err := tr.SpawnMember(context.Background(), snap.Team.ID, "m1", "coder", "{}", agent.AgentSpec{})
      require.NoError(t, err)

      // Wait for turn to complete.
      time.Sleep(200 * time.Millisecond)

      // Stop the member — this cancels the loop goroutine.
      err = tr.StopMember(context.Background(), snap.Team.ID, member.ID, StopCancel)
      require.NoError(t, err)

      // Give goroutines time to exit.
      time.Sleep(200 * time.Millisecond)

      after := runtime.NumGoroutine()
      // Allow a small delta for DB connection pool goroutines.
      assert.LessOrEqual(t, after-before, 3, "goroutine leak detected: before=%d after=%d", before, after)
  }
  ```

  Note: `MemberRunner.Stop()` calls `m.cancel()` which causes the loop goroutine to exit via `<-m.ctx.Done()`. The `defer m.cancel()` in `loop()` ensures cleanup. However, the transition-to-Stopped is immediate (Stop calls transitionLocked synchronously), so the loop goroutine exits on the next `select` iteration. The 200ms wait gives it time to drain.

## Risk assessment

| Risk | Severity | Mitigation |
|---|---|---|
| Goroutine leak in SpawnMember | HIGH | Acceptance #1 tested via `runtime.NumGoroutine` before/after. MemberRunner.Stop() cancels context → loop exits. |
| Late run overwriting canceled state | HIGH | Acceptance #5: blocking runner → cancel → unblock → assert terminal state preserved. MemberRunner has `ctx.Done()` check at handleWake:271 that returns early. |
| RWMutex deadlock (Status reads while StopTeam writes) | MEDIUM | Status uses RLock (read-only); StopMember/StopTeam use RLock (read member ptrs) then call MemberRunner methods which use their own mu. No nested lock across teamRunner.mu + MemberRunner.mu where the outer lock is a write lock. |
| StartTeam races with SpawnMember | LOW | StartTeam holds write lock during registration. SpawnMember also holds write lock for the final register step. Go's map is not safe for concurrent read+write — RWMutex protects it. |
| StopForce identical to StopCancel | LOW | For M4-02 they are the same (both call mr.Stop()). M4-07 may differentiate. Documented in Seam 4. |
| Test flakes from timing (poll loops) | MEDIUM | Use `require.Eventually` with generous timeouts where possible. Sleep-based waits capped at 5s deadlines. |
