## Task 0: M3b Migration

**File: `internal/db/migrations/20260615000000_create_mailbox_tables.sql`**

2 tables, following M3-01 FK pattern:

```sql
CREATE TABLE IF NOT EXISTS team_mailbox_messages (
    id             TEXT PRIMARY KEY,
    team_id        TEXT NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
    from_member_id TEXT NOT NULL REFERENCES team_members(id) ON DELETE CASCADE,
    kind           TEXT NOT NULL DEFAULT 'message',
    summary        TEXT NOT NULL DEFAULT '',
    payload        TEXT NOT NULL DEFAULT '{}',  -- JSON blob
    created_at     INTEGER NOT NULL             -- epoch millis
);

CREATE TABLE IF NOT EXISTS team_message_receipts (
    id          TEXT PRIMARY KEY,
    message_id  TEXT NOT NULL REFERENCES team_mailbox_messages(id) ON DELETE CASCADE,
    to_member_id TEXT NOT NULL REFERENCES team_members(id) ON DELETE CASCADE,
    delivered_at INTEGER,     -- nullable epoch millis
    read_at     INTEGER       -- nullable epoch millis
);

-- Indexes
CREATE INDEX IF NOT EXISTS idx_mailbox_team_created      ON team_mailbox_messages(team_id, created_at);
CREATE INDEX IF NOT EXISTS idx_mailbox_team_from          ON team_mailbox_messages(team_id, from_member_id);
CREATE INDEX IF NOT EXISTS idx_receipts_member_delivered  ON team_message_receipts(to_member_id, delivered_at);
CREATE INDEX IF NOT EXISTS idx_receipts_message           ON team_message_receipts(message_id);
```

`-- +goose Down` drops in reverse FK order: receipts first, then messages.

## Task 1: sqlc Queries (add to `internal/db/sql/team_queries.sql`)

1. `InsertMessage :one` — INSERT INTO team_mailbox_messages RETURNING *
2. `GetUnreadMessages :many` — JOIN receipts WHERE to_member_id=? AND read_at IS NULL
3. `InsertReceipt :exec` — INSERT into team_message_receipts
4. `MarkDelivered :exec` — UPDATE receipts SET delivered_at=? WHERE message_id=? AND to_member_id=?
5. `MarkRead :exec` — UPDATE receipts SET read_at=? WHERE message_id=? AND to_member_id=?

Note: `InsertMessage` takes `req InsertMessageRequest` not `MailboxMessage`, because `MailboxMessage` is the domain model returned from queries (it carries a `time.Time` CreatedAt), while the insert request carries the raw inputs. ## Task 5: SendMessage Service (`internal/team/mailbox.go`)

```go
type SendMessageRequest struct {
    TeamID       string
    FromMemberID string
    RecipientType RecipientType
    ToMemberID   string   // direct: specific member
    ToRole       string   // role: match role string
    Kind         MessageKind
    Summary      string
    Payload      string
}

// SendMessage resolves recipients, inserts 1 message + N receipts in one tx,
// returns the resolved recipient member IDs so the caller can Wake them.
func (s *teamService) SendMessage(ctx context.Context, req SendMessageRequest) ([]string, error)
```

Recipient resolution:
- `direct`: recipient = [req.ToMemberID]
- `broadcast`: recipient = ALL members EXCEPT from_member_id
- `role`: recipient = ALL members WHERE role = req.ToRole AND id != from_member_id

Add `SendMessage` to the `Service` interface in `service.go`.

## Design Seams

1. **M3b migration**: goose format with `-- +goose Up/Down` + `StatementBegin/End`. File name `20260615000000_create_mailbox_tables.sql`.

2. **sqlc v1.30.0 hand-authoring**: sqlc package `db` (NOT `sqlc` — master doc deviation M3-02). Params structs follow exact naming convention `OperationNameParams`. Query functions use `q.db.QueryRowContext`/`q.db.ExecContext`/`q.db.QueryContext` internally.

3. **FK pattern**: `REFERENCES team_members(id) ON DELETE CASCADE` (matches M3-01 pattern). team_mailbox_messages has FK to both `teams(id)` and `team_members(id)`.

4. **Test pattern**: `:memory:` SQLite + `goose.Up` (all migrations applied) + `newStoreFixture(t)`. Each test seeds a team + members first (FK parents required).

5. **Convert pattern**: `convert.go` owns ALL db↔domain translation. sql.NullInt64 → *time.Time for epoch millis. Non-null text stays plain string.

6. **Scope**: migration SQL + append to team_queries.sql + hand-author sqlc code + models.go + convert.go + store_mailbox.go + mailbox.go + store_mailbox_test.go. NO changes to M3-01 migration or existing stores.
