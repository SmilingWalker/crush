## Summary

5 tasks. The sequence supports all 3 StopModes (Graceful/Cancel/Force) and lives on MemberRunner. New file `shutdown.go` for the core implementation. ## Design Seams Resolved

1. **M4-01 Stop() is skeletal (Seam 1)**: Currently `Stop()` just cancels context + transitions to shutting_down then stopped. M4-07 expands this to the full 9-step sequence with proper event writing, wait loops, flush, and run terminal marking.

2. **9-step sequence mapping**: The master doc lists a 9-step sequence. The implementation maps them to concrete code operations:
   - Step 1 (stopWakeups): Set `shuttingDown` flag under mu; loop drops new wakes when flag is set
   - Step 2 (write shutdown event): Call `svc.PublishMemberEvent(ctx, teamID, memberID, "member.shutting_down")`
   - Step 3 (cancel context): For Cancel/Force: cancel immediately. For Graceful: defer cancel until after wait (step 4)
   - Step 4 (wait loop): Poll member state until idle/stopped/failed with 30s deadline (100ms poll interval). Graceful waits WITH current turn allowed to complete; Cancel cancels first then waits for drain; Force skips entirely
   - Step 5 (flush): Call `flushFn(ctx)` if set (nil-safe)
   - Step 6 (mark terminal): If `currentRunID != ""` and mode != Graceful (graceful turn completed normally), call `svc.MarkRunTerminal` with RunCanceled
   - Step 7 (stopped state): `transitionLocked(MemberShuttingDown)` then `transitionLocked(MemberStopped)`
   - Step 8 (write stopped event): `svc.PublishMemberEvent(ctx, teamID, memberID, "member.stopped")`
   - Step 9 (publish): Already done in steps 2 & 8 via PublishMemberEvent (sets PublishedAt = now)

3. **StopMode behaviour differences**:
   | Step | Graceful | Cancel | Force |
   |---|---|---|---|
   | 1 stopWakeups | yes | yes | yes |
   | 2 shutdown event | yes | yes | no |
   | 3 cancel context | after wait | immediate | immediate |
   | 4 wait loop | wait for idle (no cancel) | wait for drain after cancel | skip |
   | 5 flush | yes | yes | no |
   | 6 mark terminal | no (turn completed) | yes (RunCanceled) | yes (RunInterrupted) |
   | 7 stopped state | yes | yes | yes |
   | 8 stopped event | yes | yes | no |
   | 9 publish | yes | yes | no |

4. **PublishMemberEvent on Service**: New Service method that writes a TeamEvent with PublishedAt = now. Looks up WorkspaceID from the team store. This replaces the need for a separate "publish" step — the event is both written and published atomically.

5. **Flush function**: Added as `flushFn func(context.Context) error` on MemberRunner. Optional — nil is safe (no-op). Callers wire it via constructor or setter. The flush drains any pending async DB writes before marking the run terminal.

**Interface addition:**


**Implementation on teamService:**
```go
func (s *teamService) PublishMemberEvent(ctx context.Context, teamID, memberID, eventType string) error {
    if err := s.enabledGuard(); err != nil {
        return err
    }
    tx, err := s.db.BeginTx(ctx, nil)
    if err != nil {
        return fmt.Errorf("begin tx: %w", err)
    }
    defer func() { _ = tx.Rollback() }()
    ts := now()
    // Look up team to get workspace_id (required by team_events schema).
    team, err := s.teams.GetTeam(ctx, tx, teamID)
    if err != nil {
        return fmt.Errorf("get team: %w", err)
    }
    seq, err := s.events.NextEventSeq(ctx, tx, teamID, ts)
    if err != nil {
        return fmt.Errorf("alloc event seq: %w", err)
    }
    if err := s.events.AppendEvent(ctx, tx, TeamEvent{
        Seq: seq, ID: uuid.New().String(), WorkspaceID: team.WorkspaceID, TeamID: teamID,
        EventType: eventType, EntityType: "member", EntityID: memberID,
        ActorMemberID: &memberID, PublishedAt: &ts, CreatedAt: ts,
    }); err != nil {
        return fmt.Errorf("append event: %w", err)
    }
    return tx.Commit()
}
```

**Loop update** — check `shuttingDown` before processing a wake:
```go
func (m *MemberRunner) loop() {
    defer m.cancel()
    for {
        select {
        case <-m.ctx.Done():
            return
        case source := <-m.wakeCh:
            m.mu.Lock()
            if m.shuttingDown {
                m.mu.Unlock()
                continue // drop wake during shutdown
            }
            m.mu.Unlock()
            m.handleWake(source)
        }
    }
}
```

**Stop() update** — delegate to Shutdown with StopForce for backward compatibility:
```go
func (m *MemberRunner) Stop() {
    _ = m.Shutdown(context.Background(), StopForce)
}
```

The existing `Stop()` behaviour (cancel + transition to stopped) is preserved via Force mode which skips events and flush but still transitions to terminal state.

**Constructor update** — The existing `NewMemberRunner` signature is unchanged. `shuttingDown` defaults to false. `flushFn` defaults to nil (no-op). Callers that need flush pass it via a setter or an updated constructor (not done in M4-07 — flushFn is wired by future milestones or tests).

## Task 3: Shutdown 9-Step Sequence (shutdown.go)

New file with the core `MemberRunner.Shutdown()` method:

```go
// Shutdown executes the 9-step shutdown sequence for a member.
//   Graceful: waits for current turn, then stops (no cancel, no mark-terminal)
//   Cancel:   cancels current turn, waits for drain, marks run canceled
//   Force:    cancels immediately, marks run interrupted, skips events/flush
func (m *MemberRunner) Shutdown(ctx context.Context, mode StopMode) error {
    // Step 1: stopWakeups
    m.mu.Lock()
    if m.State == MemberStopped || m.State == MemberFailed {
        m.mu.Unlock()
        return nil // idempotent
    }
    m.shuttingDown = true
    m.mu.Unlock()

    // Step 2: write shutdown event (bg ctx — caller ctx may be cancelled)
    if mode != StopForce {
        if m.svc != nil {
            _ = m.svc.PublishMemberEvent(context.Background(), m.TeamID, m.ID, "member.shutting_down")
        }
    }

    // Step 3: cancel context
    //   Graceful: DON'T cancel — let current turn complete naturally, cancel after wait
    //   Cancel/Force: cancel immediately
    if mode != StopGraceful {
        m.mu.Lock()
        if m.cancel != nil {
            m.cancel()
        }
        m.mu.Unlock()
    }

    // Step 4: wait loop
    //   Graceful: wait for Idle/Stopped/Failed WITHOUT cancelling (turn completes naturally)
    //   Cancel:   wait for drain AFTER cancel (context.Canceled detected by handleWake)
    //   Force:    skip entirely
    if mode != StopForce {
        deadline := time.Now().Add(30 * time.Second)
        for time.Now().Before(deadline) {
            m.mu.Lock()
            state := m.State
            m.mu.Unlock()
            if state == MemberIdle || state == MemberStopped || state == MemberFailed {
                break
            }
            select {
            case <-ctx.Done():
                return ctx.Err()
            case <-time.After(100 * time.Millisecond):
            }
        }
        // Graceful: now cancel to stop the loop (we already waited for idle)
        if mode == StopGraceful {
            m.mu.Lock()
            if m.cancel != nil {
                m.cancel()
            }
            m.mu.Unlock()
        }
    }

    // Step 5: flush
    if mode != StopForce && m.flushFn != nil {
        _ = m.flushFn(context.Background())
    }

    // Step 6: mark run terminal
    //   Graceful: skip (turn completed normally via handleWake → FinishRun)
    //   Cancel/Force: mark as canceled/interrupted
    if mode != StopGraceful {
        m.mu.Lock()
        runID := m.currentRunID
        m.mu.Unlock()
        if runID != "" && m.svc != nil {
            termStatus := RunCanceled
            if mode == StopForce {
                termStatus = RunInterrupted
            }
            _ = m.svc.MarkRunTerminal(context.Background(), MarkRunTerminalRequest{
                TeamID: m.TeamID, RunID: runID, Status: termStatus,
            })
        }
    }

    // Step 7: stopped state
    m.mu.Lock()
    if m.State != MemberStopped && m.State != MemberFailed {
        m.transitionLocked(MemberShuttingDown)
        m.transitionLocked(MemberStopped)
    }
    m.mu.Unlock()

    // Step 8: write stopped event
    if mode != StopForce && m.svc != nil {
        _ = m.svc.PublishMemberEvent(context.Background(), m.TeamID, m.ID, "member.stopped")
    }

    // Step 9: publish — done in steps 2 & 8 via PublishMemberEvent (PublishedAt set)
    return nil
}
```

## Task 4: TeamRunner Integration (team_runner.go)

Update `StopMember()`, `StopTeam()`, and `CancelMemberTurn()` to call `mr.Shutdown()` instead of `mr.Stop()`.

**StopMember** — The existing graceful wait loop before Stop() is now redundant since Shutdown() handles the wait internally. Simplified:
```go
func (t *teamRunner) StopMember(ctx context.Context, teamID, memberID string, mode StopMode) error {
    t.mu.RLock()
    mr, ok := t.members[memberID]
    t.mu.RUnlock()
    if !ok {
        return fmt.Errorf("member %s not found in team %s", memberID, teamID)
    }
    return mr.Shutdown(ctx, mode)
}
```

**StopTeam** — Same simplification; each member's Shutdown handles its own wait:
```go
func (t *teamRunner) StopTeam(ctx context.Context, teamID string, mode StopMode) error {
    t.mu.RLock()
    defer t.mu.RUnlock()
    for _, mr := range t.members {
        if mr.TeamID != teamID {
            continue
        }
        _ = mr.Shutdown(ctx, mode)
    }
    return nil
}
```

**CancelMemberTurn** — The current method has inline shutdown logic (~50 lines). Replace with Shutdown:
```go
func (t *teamRunner) CancelMemberTurn(ctx context.Context, req CancelMemberTurnRequest) error {
    t.mu.RLock()
    mr, ok := t.members[req.MemberID]
    t.mu.RUnlock()
    if !ok {
        return fmt.Errorf("member %s not found in team %s", req.MemberID, req.TeamID)
    }
    // Shutdown in Cancel mode handles the full sequence:
    //   stopWakeups → event → cancel → wait → flush → markTerminal → stopped → event → publish
    return mr.Shutdown(ctx, StopCancel)
}
```

The existing CancelMemberTurn's inline state-machine logic (transition to CancelingTurn, poll loop, final transition) is all subsumed by Shutdown's 9-step sequence. The `Timeout` field from CancelMemberTurnRequest is no longer needed since Shutdown uses a fixed 30s deadline — future milestones can parameterize if needed.
