# M2-02 CancelGroup 统一取消 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add unified cancellation to M2's delegate runner — `DelegateRunner.CancelGroup(groupID)` (cancels one group's in-flight delegates, idempotent) and `DelegateRunner.CancelAllGroups()` (cancels every active group). Cancellation trips the group's `context.CancelFunc` (already wired by M2-01), every worker goroutine observes `ctx.Done()` and writes `TurnCanceled` into its `Results` slot, and the group's `Status` flips to `"canceled"`. This is the second M2 task; M2-04 (UI) and M2-05 (aggregate) consume it.

**Architecture:** M2-01's `DelegateRunGroup` already carries `ctx context.Context` + `cancel context.CancelFunc` (`delegate_types.go:58-59`), and `RunGroup` derives both from `context.WithCancel(ctx)` (`delegate_runner.go:51`) and passes `groupCtx` to every `factory.BuildRunner` + `runner.Run` call (`delegate_runner.go:112,140`). So the cancel *plumbing* exists; M2-02's job is (a) the public `CancelGroup`/`CancelAllGroups` entry points that call `group.cancel()` and flip `Status` to `"canceled"`, and (b) one **fix** to M2-01's worker result-writing path so a canceled delegate is recorded as `TurnCanceled` (not `TurnFailed`) — a real bug the acceptance criteria force us to close.

**Tech Stack:** Go 1.26.3 (`module github.com/charmbracelet/crush`), `github.com/stretchr/testify` (assert + require, the package convention). Existing package `github.com/charmbracelet/crush/internal/team` (created in M2-01). Worktree `g:/ai-project/remote-github/crush-worktrees/m2-02`, branch `m2-02-cancel`. Shell: bash on win32 (forward slashes, `/dev/null`). M2-01's mock factory/runner (`delegate_runner_test.go:20-77`) is reused as-is.

## Design seam corrections (vs master task doc `03-m2-delegate-runner.md:335-393`)

The master task doc is the approved design intent. The following are **verified implementation deviations**, each backed by cited evidence from the M2-01 codebase at agent-team tip `654cb3b6`. Every code snippet in this plan is rewritten against the real, merged M2-01 APIs.

### Seam 1: `group.cancel` already exists and the worker already respects `groupCtx` — verified

The master doc (:365) writes `group.cancel()` as if M2-02 must add the field. **Verified against merged M2-01:** `DelegateRunGroup` already has `cancel context.CancelFunc` (`internal/team/delegate_types.go:59`), `RunGroup` already sets it from `context.WithCancel(ctx)` (`internal/team/delegate_runner.go:51,59`), and every worker already passes that `groupCtx` to both `factory.BuildRunner(groupCtx, spec)` (`:112`) and `runner.Run(groupCtx, call)` (`:140`). So M2-02's `CancelGroup` only needs to **invoke** `group.cancel()`; the ctx propagation chain is complete. **Evidence:** `internal/team/delegate_types.go:47-66` (struct + comment explicitly noting "future cancel/error paths (M2-02) can reach them"), `internal/team/delegate_runner.go:50-61,112,140` (read in full during research).

### Seam 2: Idempotency requires holding `d.mu` across the lookup, OR re-checking under `group.mu` — the master doc double-locks

The master doc (`:349-368`) does `d.mu.Lock()` → lookup → `d.mu.Unlock()`, then `group.mu.Lock()` → check `Status == "canceled"` → flip → `group.mu.Unlock()`, then `group.cancel()`. This is **correct for idempotency** (the `group.mu` re-check makes a racing double-cancel safe) but has a subtle issue: between the `d.mu.Unlock()` and the `group.cancel()` call, the trailing status-flip goroutine could finish, unregister the group (`delete(d.groups, group.ID)` at `delegate_runner.go:183`), and the local `group` pointer would still be valid (Go GC keeps it alive) but the runner would no longer "know" about it. That is harmless — calling `group.cancel()` and flipping `group.Status` on an already-finished group is a no-op (cancel is idempotent; the trailing goroutine only flips `"running"`→`"done"`, never touches `"canceled"`). **Decision:** keep the master doc's two-lock structure, but add a guard so a `CancelGroup` racing with natural completion is safe: the trailing goroutine's flip only fires `if group.Status == "running"` (`delegate_runner.go:177`), so a `CancelGroup` that already set `Status = "canceled"` wins — the trailing goroutine leaves it `"canceled"`, exactly acceptance #2/#4's intent. No change to the trailing goroutine needed; verified by reading `delegate_runner.go:174-188`.

**Acceptance #3 (repeat CancelGroup does not panic):** guarded by the `group.mu` re-check of `group.Status == "canceled"` (early `return nil`). `context.CancelFunc` is itself documented safe to call repeatedly, so even without the guard it would not panic — but the guard makes a second call a cheap no-op rather than a redundant ctx-cancel. **Evidence:** `delegate_runner.go:174-188` (trailing goroutine), `context.WithCancel` doc ("After the first call, subsequent calls ... do nothing").

### Seam 3: M2-01's worker writes `TurnFailed` on cancel — must be fixed to `TurnCanceled` (LOAD-BEARING)

This is the single substantive code change beyond the two new methods, and it is a **real bug fix** the master doc did not anticipate. **The problem:** M2-01's worker result-writing path is (`delegate_runner.go:143-160`):

```go
group.mu.Lock()
if runErr != nil {
    group.Results[idx] = DelegateResult{
        TaskID: t.ID, Status: agent.TurnFailed, Error: runErr.Error(), DurationMs: dur.Milliseconds(),
    }
} else {
    group.Results[idx] = DelegateResult{... Status: res.Status, Result: res.Result ...}
}
group.mu.Unlock()
```

When `CancelGroup` trips `group.cancel()`, every worker's `runner.Run(groupCtx, call)` returns with `ctx.Err() != nil` (`context.Canceled`). The current code unconditionally maps any non-nil `runErr` to `agent.TurnFailed`. **But acceptance #2 (`03-m2-delegate-runner.md:390`) requires `group.Results[i].Status == TurnCanceled` after cancel.** So M2-01 as merged does NOT satisfy M2-02's acceptance #2 without a fix.

**Confirmed by the M2-01 mock itself:** `internal/team/delegate_runner_test.go:27-40` — when `ctx.Done()` fires, `mockTurnRunner.Run` returns `agent.TurnRunResult{Status: agent.TurnCanceled}, ctx.Err()` (line 34). The mock *intentionally* returns both the `TurnCanceled` status AND the `ctx.Err()` error. The current worker ignores the status and writes `TurnFailed`.

**Decision:** change the worker's `runErr != nil` branch to distinguish cancellation from genuine failure using `errors.Is(runErr, context.Canceled)`:

```go
group.mu.Lock()
switch {
case errors.Is(runErr, context.Canceled):
    // Cancellation (CancelGroup / parent ctx cancel): the runner returned
    // ctx.Err(). Record TurnCanceled (acceptance #2), not TurnFailed.
    group.Results[idx] = DelegateResult{
        TaskID: t.ID, Status: agent.TurnCanceled, Error: runErr.Error(), DurationMs: dur.Milliseconds(),
    }
case runErr != nil:
    group.Results[idx] = DelegateResult{
        TaskID: t.ID, Status: agent.TurnFailed, Error: runErr.Error(), DurationMs: dur.Milliseconds(),
    }
default:
    group.Results[idx] = DelegateResult{... Status: res.Status, Result: res.Result, ChildSessionID: call.SessionID, DurationMs: dur.Milliseconds()}
}
group.mu.Unlock()
```

This is a **`switch` on `errors.Is`** rather than `if res.Status == TurnCanceled` because: (1) `errors.Is(runErr, context.Canceled)` is the authoritative signal — a real `sessionAgent` may return a wrapped/derived cancel error without setting `res.Status` precisely; (2) it keeps the existing happy path (`runErr == nil` → `res.Status`) and existing `TurnFailed` path (`default`) byte-identical in behavior, so M2-01's `TestDelegateRunner_RunError` (`delegate_runner_test.go:241-257`, which feeds a non-cancel `errors.New("model timed out")`) stays green; (3) `context.DeadlineExceeded` is NOT treated as cancel — a deadline-expired delegate genuinely failed to finish its turn, so it stays `TurnFailed`. (If a future task wants deadline → canceled semantics, that is a separate, explicit decision.)

**Why not widen acceptance instead of fixing the worker?** The team-lead's task brief offered the option to relax acceptance #2 to `TurnFailed`. Rejected: `TurnCanceled` vs `TurnFailed` carries semantic weight for M2-05 (aggregate) and M2-04 (UI) — a "canceled" run is user-initiated and should be summarized differently from a "failed" run (which may need retry/error display). Recording cancel as `TurnFailed` would silently lose that distinction for every downstream consumer. The fix is 4 lines in one branch and fully tested; it is the right call. **Evidence:** `internal/team/delegate_runner.go:140-160` (current worker path), `internal/team/delegate_runner_test.go:27-40,241-257` (mock cancel return + existing RunError test).

### Seam 4: `CancelAllGroups` must snapshot IDs under `d.mu`, not range the map directly

The master doc (`:371-384`) does `d.mu.Lock(); defer d.mu.Unlock(); for id, group := range d.groups { ... group.cancel() ... }`. Two issues:

1. **Holding `d.mu` while calling `group.mu.Lock()` is a lock-ordering hazard.** M2-01's trailing status-flip goroutine takes `group.mu` then `d.mu` (`delegate_runner.go:176-184`: `group.mu.Lock()`...`d.mu.Lock()`...`delete`...`d.mu.Unlock()`). If `CancelAllGroups` takes `d.mu` then `group.mu`, that is the **opposite** order → classic AB-BA deadlock (one trailing goroutine holds `group.mu` waiting on `d.mu`; `CancelAllGroups` holds `d.mu` waiting on `group.mu`). `-race` is broken in this env (memory note), so it would not be caught automatically.
2. Calling `group.cancel()` (a `context.CancelFunc`) under `d.mu` is fine on its own (cancel does not take `group.mu`), but the `group.mu.Lock()` inside the loop is what creates the hazard.

**Decision:** `CancelAllGroups` snapshots the groups under `d.mu`, releases `d.mu`, **then** iterates the snapshot taking `group.mu` per group. This makes the only `group.mu`→`d.mu` lock order in the codebase the trailing goroutine's (unchanged), eliminating the AB-BA window. `CancelGroup` (single group) does the same: lookup under `d.mu`, release, then flip under `group.mu`. (The master doc's `CancelGroup` already releases `d.mu` before taking `group.mu` at `:350-351`, so it is already safe; only `CancelAllGroups` needs the snapshot fix.)

**Snapshot is safe wrt unregistration:** even if the trailing goroutine unregisters a group between snapshot and the per-group flip, the local `*group` pointer is still valid (GC), `group.cancel()` is a documented-repeatable no-op, and flipping `Status` to `"canceled"` on a group the trailing goroutine already flipped to `"done"` is acceptable — the group is out of the registry either way, and `"canceled"` is a strictly more-informative terminal label. To minimize that drift, the flip uses `if group.Status != "canceled"` semantics from the master doc (`:377-379`), and we additionally skip groups whose status is already terminal `"done"` (cancel of a finished group is meaningless). **Evidence:** `internal/team/delegate_runner.go:174-188` (trailing goroutine lock order), Go memory model on map iteration during concurrent delete (snapshot copy avoids it).

### Seam 5: `errors` import + `switch` style

The worker fix needs `errors.Is` → add `"errors"` to `delegate_runner.go`'s imports (alphabetically before `"fmt"`). The `switch { case ...: }` form is used (not `if errors.Is(...) else if runErr != nil`) because the three branches are mutually exclusive and the switch reads as a status-decision table, matching the agent package's preference for explicit exhaustive branches. **Evidence:** `errors` stdlib (always available); `delegate_runner.go:4-14` (current import block).

```go
// cancelGroup is the implementation behind CancelGroup, factored out so
// CancelAllGroups (Task 2) can reuse the per-group flip+cancel logic without
// re-acquiring d.mu. Task 1 ships the minimal canceling body; Task 2 adds the
// idempotency re-check under group.mu.
func (d *DelegateRunner) cancelGroup(groupID string) error {
	d.mu.Lock()
	group, ok := d.groups[groupID]
	d.mu.Unlock()

	if !ok {
		return fmt.Errorf("delegate group %s not found", groupID)
	}

	group.mu.Lock()
	if group.Status == "canceled" {
		group.mu.Unlock()
		return nil // idempotent
	}
	group.Status = "canceled"
	group.mu.Unlock()

	group.cancel() // ctx.Done() fires in every worker goroutine

	return nil
}
```

```go
// TestDelegateRunner_CancelGroup_Idempotent locks acceptance #3: calling
// CancelGroup twice on the same group does not panic and the second call is a
// no-op (returns nil). The group's Results remain TurnCanceled throughout.
func TestDelegateRunner_CancelGroup_Idempotent(t *testing.T) {
	factory := &mockAgentFactory{
		defaultDelay:  30 * time.Second,
		defaultResult: completedResult(),
	}
	runner := NewDelegateRunner(factory)

	group := runner.RunGroup(context.Background(), []DelegateTask{
		{ID: "1", Prompt: "p", AgentID: "explore"},
	})
	time.Sleep(20 * time.Millisecond)

	// First cancel: starts teardown.
	require.NotPanics(t, func() { require.NoError(t, runner.CancelGroup(group.ID)) })
	// Second cancel must be a safe no-op (the group is already flipping to
	// "canceled"; cancel() is documented repeatable, and the status re-check
	// short-circuits).
	require.NotPanics(t, func() { require.NoError(t, runner.CancelGroup(group.ID)) })

	group.Wait()
	require.Len(t, group.Results, 1)
	assert.Equal(t, agent.TurnCanceled, group.Results[0].Status)
	assert.Equal(t, "canceled", group.Status)
}
```

```go
// CancelAllGroups cancels every active delegate group the runner currently
// holds. Idempotent and safe to call concurrently with RunGroup / natural
// completion. Groups that have already reached a terminal status ("done" or
// "canceled") are left as-is; only "running" groups are flipped to "canceled"
// and have their context canceled.
//
// Lock order (Seam 4): this method snapshots the groups under d.mu, releases
// d.mu, then takes group.mu per group. This is the OPPOSITE order from the
// trailing status-flip goroutine (group.mu then d.mu, delegate_runner.go:176-
// 184), so the two can never form an AB-BA deadlock. Holding d.mu across the
// per-group group.mu.Lock() would deadlock against the trailing goroutine.
func (d *DelegateRunner) CancelAllGroups() {
	// Snapshot under d.mu; do NOT hold d.mu while taking group.mu (Seam 4).
	d.mu.Lock()
	groups := make([]*DelegateRunGroup, 0, len(d.groups))
	for _, g := range d.groups {
		groups = append(groups, g)
	}
	d.mu.Unlock()

	for _, g := range groups {
		g.mu.Lock()
		if g.Status == "running" {
			g.Status = "canceled"
			g.mu.Unlock()
			g.cancel() // safe to call after releasing group.mu (cancel takes no group.mu)
			slog.Debug("canceled delegate group", "group_id", g.ID)
		} else {
			// Already terminal ("done" via natural completion, or "canceled"
			// via a racing CancelGroup): leave it untouched.
			g.mu.Unlock()
		}
	}
}
```
