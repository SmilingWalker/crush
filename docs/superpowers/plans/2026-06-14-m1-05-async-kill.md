# M1-05 Async Sub-Agent Execution + Kill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add non-blocking (async) sub-agent execution to the coordinator: a new `runSubAgentAsync` method runs the existing sync sub-agent pipeline in a background goroutine and returns a `SubAgentHandle` for status polling and cancellation. `Cancel(sessionID)` and `CancelAll()` are extended to terminate active async sub-agents. Sync behavior (`runSubAgent`) is unchanged.

**Architecture:** `runSubAgent` (sync, unchanged) becomes the reusable core. `runSubAgentAsync` wraps it in a goroutine on a derived cancellable context, streams `SubAgentStatus` onto a buffered channel (`running` → terminal `done`/`error`/`canceled`), and unregisters itself on exit. The coordinator tracks in-flight runs in `activeSubAgents map[string]*activeSubAgent` (keyed by RunID, value carries the cancel func + owning SessionID) under a `sync.RWMutex`. `Cancel`/`CancelAll` walk that map. The `agent` tool handler is NOT touched — it keeps calling the sync `runSubAgent`.

**Tech Stack:** Go 1.24, `context`, `sync`, `github.com/google/uuid v1.6.0`, `charm.land/fantasy`, `github.com/stretchr/testify`. Module `github.com/charmbracelet/crush`. ## Design seam corrections (vs master task doc `02-m1-subagent-foundation.md:744-1015`)

The master task doc is the approved design. The following are **implementation refinements**, recorded here so the reviewer and the M1-06 author see the deviations:

1. **No `runSubAgent(ctx, params) (interface{}, error)` dispatch entry.** The task doc's改动4 unifies sync/async behind one `interface{}`-returning entry. That forces the handler (`agent_tool.go:92`) to type-assert and loses compile-time safety for zero benefit — M1-05's handler only ever calls sync. Instead: `runSubAgent` keeps its current `(fantasy.ToolResponse, error)` signature (the sync core), and `runSubAgentAsync` is a separate, type-safe `(SubAgentHandle, error)` method. `agent_tool.go` is unchanged.

2. **Cancel detection uses `ctx.Err()`, not `errors.Is(err, context.Canceled)`.** `runSubAgent` swallows an `agent.Run` failure into `fantasy.NewTextErrorResponse(...)` with `err == nil` (see `coordinator.go:1150-1152`). So after `runSubAgent` returns inside the async goroutine, we check `ctx.Err() != nil` to reliably classify a cancellation, regardless of which layer observed the canceled context.

3. **`activeSubAgents` keyed by RunID, value is `*activeSubAgent{cancel, sessionID}` — NOT `strings.Contains(runID, sessionID)`.** The task doc's改动5 matches sub-agents to a session via `strings.Contains(runID, sessionID)`, but RunID is a UUID unrelated to SessionID, so it never matches. We carry the owning SessionID in the record and compare it directly.

4. **No `SubAgentMode` type / `subAgentParams.Mode` / `AgentID` / `ActorCtx` fields.** The task doc's改动1-2 add a `SubAgentMode` enum and three params fields. With no unified dispatch entry (correction #1), `Mode` has no consumer — sync/async are distinguished by method name, which is more Go-idiomatic and type-safe. `AgentID`/`ActorCtx` are consumed only by M1-06 (`AgentToolResult`) and M2, so they are deferred to those milestones (YAGNI for M1-05's acceptance criteria).

5. **`SubAgentStatus.Result` is `*fantasy.ToolResponse`, not `*AgentToolResult`.** `AgentToolResult` is defined in M1-06 (`agent_result.go`, task doc:1019). M1-05 must not forward-reference it. M1-06 will migrate this field when it introduces the structured result.

```go
import (
	"context"
	"errors"

	"charm.land/fantasy"
	"github.com/google/uuid"
)

// runSubAgentAsync launches params in a background goroutine and returns a
// SubAgentHandle immediately (non-blocking). The goroutine runs the existing
// sync pipeline (runSubAgent) on a derived cancellable context, streams status
// onto handle.StatusChan, and unregisters itself on exit.
//
// A run is classified as "canceled" when ctx.Err() is non-nil after runSubAgent
// returns — runSubAgent itself swallows agent.Run failures into an error
// response with err == nil, so ctx.Err() is the reliable signal.
func (c *coordinator) runSubAgentAsync(ctx context.Context, params subAgentParams) (SubAgentHandle, error) {
	runID := uuid.New().String()
	ctx, cancel := context.WithCancel(ctx)

	c.activeSubAgentsMu.Lock()
	c.activeSubAgents[runID] = &activeSubAgent{cancel: cancel, sessionID: params.SessionID}
	c.activeSubAgentsMu.Unlock()

	statusChan := make(chan SubAgentStatus, 10)
	handle := SubAgentHandle{
		RunID:      runID,
		StatusChan: statusChan,
		Cancel:     cancel,
	}

	go func() {
		defer close(statusChan)
		defer func() {
			c.activeSubAgentsMu.Lock()
			delete(c.activeSubAgents, runID)
			c.activeSubAgentsMu.Unlock()
		}()

		statusChan <- SubAgentStatus{State: subAgentStateRunning, Progress: "starting"}

		result, err := c.runSubAgent(ctx, params)
		if ctx.Err() != nil {
			statusChan <- SubAgentStatus{State: subAgentStateCanceled, Error: ctx.Err()}
			return
		}
		if err != nil {
			state := subAgentStateError
			if errors.Is(err, context.Canceled) {
				state = subAgentStateCanceled
			}
			statusChan <- SubAgentStatus{State: state, Error: err}
			return
		}

		statusChan <- SubAgentStatus{State: subAgentStateDone, Result: &result}
	}()

	return handle, nil
}
```
