# M4.5: Leader Team Tools — Design Spec

> Date: 2026-06-16 | Status: approved design | Scope: 4 tools + wiring

## Goal

Give the main coder agent the ability to create teams and spawn members through normal chat conversation. User says "split this into 2 members" → model calls `team_create` + `team_spawn_member` → MemberRunners spin up.

## Background

M4 built the complete backend (MemberRunner, TeamRunner, Scheduler, Mailbox, etc.) and wired it into App. But the main coder agent has no tools to invoke it. The missing piece:

```
User chat → coder agent → [team_create / team_spawn_member] → TeamRunner → MemberRunner → real agent
```

## Design

### 4 new leader tools

| Tool | Type | Input | Behavior |
|---|---|---|---|
| `team_create` | Write | name, description | Service.CreateTeam + TeamRunner.StartTeam |
| `team_spawn_member` | Write | team_id, name, role, model_type?, permission_mode? | Service.SpawnMember + TeamRunner.SpawnMember |
| `team_list` | Read | workspace_id (optional) | Service.ListTeams; if workspace_id empty, returns empty list with hint to provide workspace_id |
| `team_status` | Read | team_id | TeamRunner.Status() → member states + active runs + cost |

### Tool injection

Tools are `fantasy.AgentTool` closures capturing `Service` + `TeamRunner`. They are appended to the coder agent's existing tools via `SessionAgent.AppendTools()` — the same mechanism M4-06 used for member tools.

The injection happens in `app.InitCoderAgent()` after the coordinator is created, gated behind `IsAgentTeamEnabled()`.

### team_spawn_member AgentSpec defaults

- `model_type`: defaults to `"inherit"` (use coder's model)
- `permission_mode`: defaults to `"default"` (ask user)
- `system_prompt`: auto-generated from member role + team context

### Gate

All 4 tools check `IsAgentTeamEnabled()`. When the config flag is false, tools return "agent team feature is not enabled — set agent_team: true in config".

## Demo flow

```
User: "帮我把这个项目拆成2个队员，一个做前端一个做后端"

Model:
1. team_create("feat-project") → {team_id: "team-123"}
2. team_spawn_member("team-123", "frontend-dev", "programmer") → {member_id: "m1"}
3. team_spawn_member("team-123", "backend-dev", "programmer") → {member_id: "m2"}
4. → "已创建团队 feat-project，m1(前端) 和 m2(后端) 已启动"
```

## Acceptance criteria

1. `team_create` creates team in DB + starts via TeamRunner
2. `team_spawn_member` spawns member in DB + starts MemberRunner
3. `team_list` returns all teams for the workspace
4. `team_status` returns live member states from TeamRunner
5. All 4 tools return friendly message when gate is off
6. Coordinator.AppendTools correctly delegates to currentAgent
7. `go build ./...` passes; `go test ./internal/team/... ./internal/agent/...` passes (known flakes excluded)

## Out of scope (M5+)

- Permission approval UI for spawned members (M5)
- Task assignment to members by leader (requires task tools for leader)
- Member shutdown/cancel from leader tool (next iteration)
